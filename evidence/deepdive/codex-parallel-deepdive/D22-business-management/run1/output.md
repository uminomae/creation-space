# D22 codex-parallel-deepdive Run1

## スコープ

本 Run1 は、D22 の既存 Level 2 資料を再読し、`codex-parallel-deepdive` 形式で次の4系統を並列に整理した。

- 既存11件の監査
- 欠落候補の抽出
- 境界・過適合ガード
- 5段階カバレッジの再配置

入力は `evidence/evidence-D22-business-management.md`、GPTレビュー、RECONCILE、公開ドメインレポート、DR-D22 一次ソースの5点。

## 統合結論

- 既存11件は全件維持でよい。ただし 11/11 `Revise` 前提。
- Run1 時点で `Accept -> CA` や `Accept -> Reject` に落とす決定打はない。
- ただし強度は均一でない。`003` / `007` / `009` はアンカー、`002` / `010` / `011` は高リスク再記述枠として扱うべき。
- D22 の厚みは `縁 -> 渦` と `束の制度化` にある。逆に `場への入口` と `特性/過程の切り分け` は弱い。

## 既存11件の統合判定

| クラスタ | ID | 位置づけ |
|---|---|---|
| Anchor | `003` `007` `009` | D22 の縁判定と関係形成を校正する基準セット |

## 既存11件への実務的含意

- `EV-D22-003` は D22 の最も素直な段階アンカーだが、`Adjourning` を束へつなぐ残存構造の記述が必要。
- `EV-D22-007` は `縁` の校正基準として最も使いやすい。Run2 でも基準理論として維持する。
- `EV-D22-009` は起業家論の縁アンカー。後半段階を広げ過ぎないことが重要。
- `EV-D22-006` は「縁が弱い理論を弱いまま残す」安全弁として価値がある。
- `EV-D22-002` / `010` / `011` は魅力が高く、だからこそ本文側で制御しないと過適合の入口になる。

- 特性理論を生成過程に変換しない。
- 補助理論を主証拠にしない。
- 縁の空白を欠陥扱いしない。
- D21 境界理論は「経営過程として不可欠か」でふるい直す。

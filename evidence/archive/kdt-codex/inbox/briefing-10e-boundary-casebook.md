## 1. Context（タスクの背景）

REPORT-抱持-observability.md §Bは6組の境界判定ガイドを提供した。しかし判定ガイドは**抽象的な指標と質問**であり、実際の場面でどう使うかのイメージが薄い。

本タスクは、最も紛らわしい3境界（3↔4, 4↔5, 5↔6）について**具体的なケース（会話断片＋観測＋判定＋支援者の次の一手）**を構築し、師弟ユースケースでの実用度を上げる。

### 対象境界（3組）

| 境界 | 核心的差異（REPORT-抱持-observability.md §Bより） |
|------|------|
| 3↔4 | 「保持を開始するが短時間で閉じる」vs「保持しているように見えるが探索が起きない」 |
| 4↔5 | 「個人内で固着」vs「二者系で保持が成立する」 |
| 5↔6 | 「外的Containerが主」vs「外的支援なしでも一定は保持できる」 |

## 2. Scope（作業範囲）

### §A-§C: 各境界のケースブック（3境界×3-5ケース）

各ケースは以下の構造で記述する：

#### ケース構造

```markdown
### ケース [境界]-[番号]: [短いタイトル]

**場面**: [対人支援/師弟/チーム/1on1 等の文脈]（1-2文）

**会話断片**:
> [当事者の発言1]
> [支援者の発言1]
> [当事者の発言2]
（3-6ターン。自然な会話として読めること）

**観測（4観点）**:
- 言語的: [何が見えるか]
- 行動的: [何が見えるか]
- 身体的: [何が見えるか]（観測できない場合は「観測困難」）
- 内省的: [当事者の内省として想定されること]（推定。[SPECULATIVE]可）

**判定**: 段階[X]寄り。根拠: [REPORT-抱持-observability.mdの判定質問ID or §B境界の判定基準]

**支援者の次の一手**:
- 推奨: [何をするか]（Container類型＋具体的アクション）
- 回避: [何をしないか]（TASK #10dの「やってはいけない」参照。なければ独自に記述）

**Evidence**: [EV-ID]
**タグ**: [該当するSafety Valveタグ]
```

### ケース設計の原則

1. **3-5ケース/境界**。最低3ケース、Evidenceが豊富なら5ケースまで
2. **文脈の多様性**: 同じ境界でも異なる場面（師弟、上司部下、チームファシリテーション、セルフケア等）を含める
3. **紛らわしさの段階**:
   - 1ケース: 明確にどちらかの段階（判定の練習用）
   - 1-2ケース: 紛らわしい（どちらとも取れるが、手がかりで判定できる）
   - 1ケース: 誤判定ケース（最初は段階Xに見えるが実は段階Y。§Bの誤判定パターンの具体化）
4. **会話断片はリアルに**: 教科書的でなく、実際の対話で起きそうな言い回しを使う
5. **判定の根拠を明示**: REPORT-抱持-observability.mdの判定質問ID（L0-1, L1-3等）を参照

### §D: 境界横断パターン（3境界を統合）

3境界のケースを横断的に分析し、以下を記述する：

1. **「上方向の移行」の兆候**: 段階3→4→5→6へ移行するときに共通して見られるもの（あれば）
2. **「退行」の兆候**: 逆方向（6→5→4→3）に落ちるときに共通して見られるもの（あれば）
3. **判定の難易度ランキング**: 3境界のうち、どれが最も判定が難しいか。実用上の注意

## 3. Vocabulary Constraints（用語制約）

### 必ず使う用語

| 用語 | 意味 | 注意 |
|------|------|------|
| D1-D4 | コア定義 | |
| Layer 0-3 | 4層モデル | 必ず番号付き |
| 生存軸, 信頼軸 | | 混同しない |
| 抱持 | 大文字W | |
| Container | 大文字C | |
| 段階1-7 | TASK #10の名称を正確に | |
| Container6類型 | 対人的/制度的/対話的/外部化/身体的/文化的 | 「次の一手」で使用 |

### 使ってはいけない用語

| 禁止 | 理由 | 代替 |
|------|------|------|
| 実在する個人名・組織名 | ケースは架空であること | 匿名・抽象化 |
| 「治療」「診断」 | 臨床ツールではない | 「支援」「判定」 |
| 「この人は段階Xの人」 | 人のラベル化 | 「この時点では段階X寄りの兆候」 |
| 「正解」「正しい判定」 | 判定は示唆であり確定ではない | 「段階X寄りと判定できる」 |

### 会話断片の用語制約

- 当事者の発言: 理論用語（D1-D4, Layer, 生存軸/信頼軸等）を**使わない**。日常語で書く
- 支援者の発言: 理論用語は**最小限**。支援者が内心で使う分析フレームと、実際に口にする言葉は分けること
- 観測セクション: 理論用語を使ってよい（分析視点なので）

## 4. Safety Valves（安全弁）

| タグ | 使用場面 |
|------|---------|
| `[UNCERTAIN]` | 判定がどちらとも取れるケースの判定セクション |
| `[SPECULATIVE]` | 内省的兆候の推定、会話断片の架空性に起因する限界 |
| `[CONTEXT_DEPENDENT]` | 同じ会話でも関係の質や文脈で判定が変わりうる場合 |
| `[SELF-REPORT_BIAS]` | 当事者の自己報告が歪みやすい場面 |

**重要**:
- ケースは**架空**である。「実例に基づく」とは書くな。「典型的な場面として構成した」と明記せよ
- 誤判定ケースには必ず**「なぜ誤判定が起きやすいか」の説明**を付けること
- 「支援者の次の一手」は1つの正解ではなく、**推奨と回避の対**で書くこと

## 8. 注意事項

- **ケースはリアルさが命**。教科書的な「模範回答」のような会話にしない。当事者の言葉には迷い・矛盾・言い淀みを含めること
- 誤判定ケースは**最も教育的価値が高い**。「一見こう見えるが実は違う」を丁寧に書け
- 「支援者の次の一手」は、TASK #10d（Container対応表）が存在すればそちらを参照する。存在しなければ、Container6類型の枠組みで独自に記述
- 会話断片の長さに注意: 短すぎると判定材料が足りず、長すぎると焦点がぼける。3-6ターンを厳守
- **ビジネス文脈のケースを必ず含める**: 師弟関係だけでなく、1on1/チーム会議/プロジェクトレビュー等の場面。本プロジェクトの射程は事業を主対象とする
- TASK #10c, #10dの出力が存在すれば参照し、ケースの精度を上げよ。存在しなければ現行版で進行

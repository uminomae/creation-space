# 破壊的変更チェックリスト

## 定義

以下は「破壊的変更」として扱い、このチェックリストを適用する。

- フィールド名・キー名の変更
- データ構造の変更
- ファイル形式・バージョンの変更
- API のレスポンス構造変更
- 生成物のスキーマ変更

## チェックリスト

破壊的変更を行う前に、以下を確認する。

### 1. 下流消費者の列挙（必須）

変更対象を消費する全てのファイル・スクリプト・システムを列挙する。

```text
変更対象: {ファイルパス}
下流消費者:
  1. {ファイル} - {どのフィールドを使っているか}
  2. {ファイル} - {どのフィールドを使っているか}
```

`grep` / `rg` で変更するフィールド名を検索し、参照箇所を網羅する。

### 2. 影響範囲の評価

各下流消費者について、以下を確認する。

- 変更後も正しく動作するか
- フォールバックコードが必要か
- 同時に修正が必要か

### 3. 同時修正の実施

破壊的変更と下流の修正は同一コミット、または同一 Agent タスクで行う。
分離すると中間状態で不整合が発生する。

### 4. Agent subagent への委任時

Agent プロンプトに以下を必ず含める。

```text
## 下流消費者（変更時に同時更新が必要）
- {ファイル1}: {フィールド名} を参照
- {ファイル2}: {フィールド名} を参照
```

## 適用場面

- Agent subagent のプロンプト作成時
- CLI 指示書作成時
- Main が直接編集する場合

## 0. このスキルの役割

CLI 指示書を作成する際に **必ずロードされるスキル**。
テンプレートの読み込みを「ルールで書いてチェックする」のではなく、
「スキルとしてファイルが読まれること自体が保証」に変える。

### 他スキルとの棲み分け

| スキル | 責務 |
|---|---|
| **本スキル** | CLI指示書の作成手順・テンプレート・チェックリスト |
| project-management | プロジェクト棚卸し・教訓記録・スキル昇格原則 |
| doc-management | Memory/README/SKILL の肥大化整理 |

## 1. 指示書作成手順

### Step 1: テンプレートを読む

本スキルをロードした時点で §2 の構造が頭に入る。

### Step 2: 指示書を書く

§2 テンプレートに従い、作業固有のステップを埋め込む。

必須要素:
- **Step 0（前提確認）** - ブランチ確認等
- **作業手順（Step 1〜N）**
- **検証手順**
- **commit & push**
- **Step 完了報告** - 最終出力末尾に `model` / `tokens used` を記載（Codex 向け）
- **Step 最終（完了処理）** - Issue コメント + DONE ファイル作成

### Step 3: チェックリスト（§3）でセルフチェック

### Step 4: inbox に配置

```
.cache/inbox/_instructions-{issue}-{slug}.md
```

### Step 5: backlog があれば更新

## 2. テンプレート

### 必須構造

```
# CLI指示書: {タイトル}
**担当**: Claude Code CLI
**ブランチ**: {ブランチ名}
**前提**: {前提条件}
**関連 Issue**: #{番号}
**reasoning**: {high | xhigh}（§4 選択基準を参照）

## Step 0: 前提確認（作業開始前に必ず実行）
→ ブランチ確認

## 作業手順
→ Step 1〜N

## 検証

## commit & push

## コミット影響レビュー
→ skills/commit-review-with-log/SKILL.md Phase 1-3

## Step 完了報告（Codex 向け・必須）
→ 最終出力末尾に `model` / `tokens used`

## Step 最終: 完了処理
→ Issue コメント + DONE ファイル作成

## 完了条件
```

## 3. チェックリスト

指示書を書き終えたら、以下を全て確認する。

### 全指示書共通

- [ ] Step 0（前提確認）が含まれているか
- [ ] Step 最終（Issue コメント + DONE ファイル）が含まれているか
- [ ] Codex 向け指示書の場合、完了報告フッター（モデル名・token数）が含まれているか
- [ ] 完了条件にコミット手順が含まれているか
- [ ] **commit を含む指示書に コミット影響レビュー が含まれているか**
- [ ] **レビュー結果の報告先（Issue コメント）が明示されているか**
- [ ] 出力先ディレクトリの README.md を確認したか

### スキル新設・変更を伴う場合

- [ ] `skills/project-management/SKILL.md` §0 の影響範囲チェックリストを確認したか

## 4. 判断基準

### いつ CLI 指示書を書くか

| 状況 | 判断 |
|---|---|
| git commit/push を伴う | → CLI指示書 |
| 複数ファイルの編集 | → CLI指示書 |
| バッチ処理・一括変換 | → CLI指示書 |
| .cache/ 内のみの変更 | → DT App 直接でよい |
| 単一ファイルの軽微な修正（cache以外） | → 確認して判断 |

### Codex reasoning effort の選択基準

指示書ヘッダーに `**reasoning**:` を記載し、タスク特性に応じて使い分ける。

| reasoning | タスク特性 | 例 |
|---|---|---|
| `high` | 機械的検証・形式チェック・ファイル操作・一括変換 | 残骸検出、クロスリファレンス、形式統一、リネーム |
| `xhigh` | 解釈・判断・分析・設計を伴う | 理論的レビュー、設計判断、レコンサイル、品質評価 |

**判断に迷ったら `high` を選ぶ。**

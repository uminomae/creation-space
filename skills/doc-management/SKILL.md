# 書類管理スキル（スパデー）

**バージョン**: 1.0
**作成日**: 2026-03-15
**移植元**: 旧 private repo skills/doc-management/SKILL.md v1.1
**原則**: README = IF-ELSEディレクトリのみ。詳細はSKILLへ委譲。Memoryは最小限。

---

## 0. 設計思想

### なぜ定期整理が必要か

- Memoryは項目が増えるほど矛盾リスクと文脈肥大が増す
- README/SKILL.mdも同様。追加し続けると「読む量」が増え、本来不要な文脈がAIに入る
- 解決策: 定期的なスパデー（統合・矛盾除去・委譲）

### READMEの正しい役割

```
README.md = IF-ELSEディレクトリ
  「このタスクならこのSKILL.mdを読め」
  「このフェーズならこのファイルを読め」
  詳細はすべてSKILL.mdに委譲する
```

READMEに詳細な手順・ルールを書かない。書くならSKILL.mdへ切り出す。

### Memoryの正しい役割

```
Memory = 好み・禁止・原則（Rules）+ タスク別ポインタ（IF-ELSE）
  詳細手順はSKILL.mdに委譲
  「何をするか」ではなく「どう振る舞うか」「どこへ行くか」
```

Memoryに手順・ワークフロー・技術詳細を書かない。

## 1. スパデートリガー

| トリガー | 判断基準 |
|---------|---------|
| Memory 件数 | 20件超 |
| Memory 矛盾検出 | 2件以上が相互矛盾または重複 |
| README バージョン | メジャー更新（x.0）の節目 |
| README.md サイズ | 30KB超 |
| CLAUDE.md 行数 | 250行超 |
| 体感的劣化 | AIがルールを守れていない・混乱している |
| マイルストーン完了 | 大きな作業フェーズが終わった直後 |
| オーナー指示 | 「整理して」と言われたとき |

---

## 2. Memory スパデー手順

### Step 1: 全件表示

Memory の全件を確認する。

### Step 2: 分類

各項目を以下の4種に分類する：

| 種別 | 定義 | 対処 |
|------|------|------|
| **A: 原則・禁止（保持）** | 「何をしてはいけないか」「どう振る舞うか」 | そのまま保持 |
| **B: ポインタ（保持・短縮可）** | 「このタスクにはこのSKILLを使え」 | 1行に圧縮 |
| **C: 詳細手順（委譲）** | ワークフロー・技術詳細・ファイルパス | SKILL.mdへ移動後に削除 or 1行ポインタに |
| **D: 陳腐化（削除）** | 現状と乖離・完了済みフェーズのルール | 削除 |

### Step 3: 矛盾チェック

- 同じ操作に対して相反する指示がないか
- 同じ内容が複数項目に分散していないか
- 古いフェーズのルールが残っていないか

### Step 4: 実行

- D（陳腐化）→ 削除
- C（詳細手順）→ SKILL.mdに移動し、Memoryは1行ポインタに
- B（ポインタ）→ 冗長なら圧縮
- A（原則）→ 必要なら文言整理

### Step 5: 確認

整理後に全件確認。20件以内・矛盾なしを確認。

---

## 3. README スパデー手順

### Step 1: 現状把握

README.mdを読み、以下を確認：
- セクションごとの「役割」が明確か
- 詳細手順がREADMEに直書きされていないか
- リンク集に古い・存在しないファイルがないか

### Step 2: 分類

| 種別 | 定義 | 対処 |
|------|------|------|
| **エントリポイント** | 「このタスクにはここへ」のIF-ELSE | 保持・整理 |
| **詳細手順** | 具体的なコマンド・ワークフロー | SKILL.mdへ切り出し、READMEはリンクのみ |
| **現状情報** | 状況依存の記述 | 実態に合わせ更新 |
| **古い履歴** | 6ヶ月以上前の更新履歴 | 削除（アーカイブ） |

### Step 3: 実行

- 詳細手順をSKILL.mdへ移動し、READMEは「→ skills/xxx/SKILL.md」に置換
- 現状セクションを現在の主作業に合わせて更新
- 古い履歴を直近6件程度に絞る

### Step 4: バージョン更新

- 軽微な整理: マイナー更新
- 大きな構造変更: メジャー更新

---

## 4. SKILL.md スパデー手順

### Step 1: 一覧確認

```
ls skills/
```

### Step 2: 各SKILLを評価

| 評価軸 | 問い |
|--------|------|
| **現役性** | このSKILLを最後に使ったのはいつか？今後使うか？ |
| **呼び出し可能性** | READMEのIF-ELSEから辿れるか？ |
| **重複** | 他のSKILLと内容が重複していないか？ |
| **肥大化** | 1つのSKILLが複数の責務を持っていないか？ |

### Step 3: 対処

- 使わないSKILL → オーナーに削除確認
- 重複 → 統合（オーナー承認後）
- 肥大化 → 分割（オーナー承認後）
- 呼び出し不可 → READMEのIF-ELSEに追加

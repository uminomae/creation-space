# プレゼンテーションテンプレート v1.0

**対象コンテンツ**: ドメインレポート（`domain-D{NN}-{slug}-academic-ja.md`）のプレゼン資料化
**出力形式**: Markdown スライド（`---` 区切り、H2 がスライドタイトル）
**スライド数**: 8-12 枚
**継承元**: `reader-rules-creation-report.md` の禁止事項・声の設計を継承

---

## 生成ルール

### ソース

- 対象ドメインレポート（`transform/domains/publish/domains/domain-D{NN}-{slug}-academic-ja.md`）を必ず Read してから生成すること
- ドメインレポートに書かれていない内容を追加しない
- 数値（理論数、対応判定の分布等）はレポートの記載に忠実に転記する

### 禁止事項（reader-rules-creation-report.md 継承）

- **NL-005**: 欠損駆動思考への言及禁止。5段階モデルとの構造類似の調査がテーマであり、欠損駆動思考の正当化ではない
- **NL-010**: 抱持・欠損（Kesson）への言及禁止
- **NL-013**: AI由来ソースは三人称の報告体で記述
- 「私」「あなた」は使わない。「本調査では」「この領域では」を使う
- 著者の感想、AI作業環境、ツール名は書かない

### 声の設計

- です・ます調
- 解説番組のナレーション的な明晰さ
- 一文で一つのことを言う
- 専門用語は初出時に簡潔に説明を添える

### スライド書式

- 各スライドは `---` で区切る
- H2（`##`）がスライドタイトル
- 箇条書きを活用し、1スライドの情報量を抑える
- テーブルは構造対応の一覧で使用する
- front matter は出力ファイルの先頭に付与する

## ビジュアルデザイン指針（v2.0）

### スライドタイプ別スタイリング

CSS が各スライドを自動分類する。生成時にスライドの役割を意識すること:

| スライド# | タイプ | CSSクラス | デザイン特性 |
|---|---|---|---|
| 1 | タイトル | `slide-title` | 中央揃え、大見出し、グラデーション下線 |
| 2 | 概要 | `slide-overview` | ガラスモーフィズムカード化された箇条書き |
| 3 | 5段階モデル | `slide-table` | コンパクトテーブル、モノスペースヘッダ |
| 4 | 理論一覧 | `slide-table` | 同上 |
| 5-7 | 主要エントリ | `slide-entry` | 散文用高密度レイアウト、ラベルバッジ |
| 8 | 横断パターン | `slide-patterns` | 箇条書き + アクセントカラー |
| 9 | 未解決の問い | `slide-questions` | 引用スタイル |
| 10 | 結論 | `slide-conclusion` | 区切り線付きリスト、グリーンアクセント |

### エントリスライドの構造化

主要エントリ（スライド5-7）は密度が高い。以下のフォーマットを推奨:

```markdown
## 主要エントリ 1: {理論名}

- **概要**: {理論の簡潔な説明}
- **構造対応**: {どの段階に対応するか}
- **注目点**: {なぜこの理論が示唆に富むか}
```

旧フォーマット（散文 + 太字ラベル「事実として」「読み取りとして」「解釈として」）も CSS で自動スタイリングされる。

### 図解の使用指針

**義務**: domain presentation は、タイトル/概要の直後に **構造対応図の SVG スライドを必ず1枚入れる**。  
teaser・PDF 冒頭などで使う PNG とは用途を分ける。slide viewer では SVG を正本とし、PNG は teaser / report PDF 用の派生物として扱う。

各スライドタイプに適した図解パターン:

| スライドタイプ | 推奨図解 | 用途 |
|---|---|---|
| タイトル | なし（テキストのみ） | — |
| 5段階モデル | SVG: 5段階フロー図 | 視覚的な段階理解 |
| 理論一覧 | テーブルで十分 | — |
| 主要エントリ | SVG: 構造対応マッピング図 | 理論↔段階の対応可視化 |
| 横断パターン | SVG: ベン図/ネットワーク図 | 共通点の可視化 |
| 結論 | SVG: サマリーダイアグラム | 全体像の俯瞰 |

SVGファイルは `assets/svg/domains/` に配置し、presentation では title/overview の次に参照する:
```markdown
## 構造対応図

![構造対応図](https://uminomae.github.io/creation-space/assets/svg/domains/domain-D{NN}-{name}.svg)
```

ドメイン slug と SVG ファイル名が一致しない場合があるため、`assets/svg/domains/domain-D{NN}-*.svg` の実在ファイルを優先して参照する。

### カラーセマンティクス

テーブルやラベルで使う判定用語にはCSS側で色が付く。生成時は以下の太字キーワードを使用:
- **強い対応** → 青系アクセント
- **部分的な対応** → 紫系アクセント
- **条件付きの対応** → アンバー系
- **対応なし** → ローズ系

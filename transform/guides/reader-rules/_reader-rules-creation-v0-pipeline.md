**対象コンテンツ**: M2スピノル5段階（場→波→縁→渦→束）

**関連issue**: kesson-driven-thinking #5（TASK#30）/ techo #2

## §0 設計原則

### 3層構造

```
【DB層】base/text/m2-creation-process/     ← 正本。シンプルmd
    ↓ 変換層（本ファイル）
【UI層①】Jekyll記事（pjdhiro/_posts/）
【UI層②】JS HTMLパース（kesson-space / 静的ページ）
【UI層③】PDF（pandoc経由）
```

### ソースmdの互換性要件

ソース（DB層）は以下のみで書く。出力側が解釈する。

| 要素 | 使用可 | 禁止 |
|------|--------|------|
| 見出し | `#` `##` `###` | `####` 以下（深すぎる） |
| 強調 | `**bold**` `*italic*` | HTML直書き |
| リスト | `-` `1.` | ネスト3階層超 |
| 引用 | `>` | |
| テーブル | GFM table | 複雑な結合 |
| 区切り | `---` | |
| リンク | `[text](url)` | Liquid `{{ }}` タグ |
| 画像 | `![alt](path)` | 絶対URLのみ推奨 |
| コードブロック | ` ``` ` | |
| front matter | YAML `---` ブロック | Jekyllセクション変数 |

**禁止**: Liquidタグ、LaTeX、HTML埋め込み、{: .class} IAL  
→ これらは**変換層が付与**する。ソースに書かない。

## §1 ソースmd構造（DB層テンプレート）

```markdown
---
id: creation-v1
title: 創造とは
subtitle: 場から束へ——生成の5段階
tags: [M2, creation, five-stages]
schema: five-stages
version: 1.0
---

## はじめに

（導入文。200字以内）

## Step 1 場（Field）

**構造**: 〜  
**プロセス**: 〜  
**イメージ**: 〜

（本文。各300字以内）

## Step 2 波（Wave）

...（以下 Step 3〜5 同形式）

## 領域横断の類似概念

（群盲象チェック。3領域以上）

### 哲学・思想

...

### 数学・物理

...

### 心理学

...

## 注記

（[P][M][S]タグの補足。最終出力では削除）
```

**ポイント**:
- `##` = セクション区切り（3出力共通のチャンク単位）
- front matterの `id`, `schema`, `tags` が変換スクリプトのメタ情報になる
- [P][M][S]タグは `## 注記` セクションにまとめ、UI層出力時に除去する


### 変換処理（blog固有）

| ソース要素 | Jekyll出力 |
|-----------|-----------|
| `## Step N タイトル` | `## 0N. タイトル`（ゼロ埋め番号） |
| front matterの `---` | Jekyllが処理。本文から除去 |
| `## 注記` セクション | **削除**（出力しない） |
| 画像 `![alt](path)` | `[![alt]({{ path \| relative_url }})]({{ path \| relative_url }})` に変換 |
| dark CSS | AI生成本文直前に挿入（`blog-dark-theme-css.md` 参照） |

### 構成テンプレート

```
[pjdhiro冒頭まとめ（7項目以内）]  ← pjdhiroが書く
  ↓
## 以下はClaudeが生成しました。コピペです。
  ↓
<style>（dark CSS）</style>
  ↓
{: .notice--info}
M2（スピノル5段階）の内容を一般向けに再構成した記事です。
  ↓
## 01. はじめに
...（変換済み本文）
  ↓
## 06. 領域横断の類似概念
  ↓
```

## §3 JS HTMLパース出力ルール（UI層②）

**用途**: kesson-space またはスタンドアロン静的ページでのインタラクティブ表示  
**パースルール**: `data-*` 属性で semantic HTML に変換する

### HTMLタグマッピング

| ソースmd要素 | HTML出力 |
|-------------|---------|
| `## Step N タイトル` | `<section class="creation-step" data-step="N" data-title="タイトル">` |
| `## はじめに` | `<section class="creation-intro">` |
| `## 領域横断の類似概念` | `<section class="creation-analogy">` |
| `### 哲学・思想` 等 | `<div class="analogy-domain" data-domain="philosophy">` |
| `**構造**: ...` | `<dl><dt>構造</dt><dd>...</dd></dl>` |
| `**プロセス**: ...` | `<dl><dt>プロセス</dt><dd>...</dd></dl>` |
| `**イメージ**: ...` | `<div class="step-image-hint">...</div>` |
| front matter | `<script type="application/json" id="creation-meta">...</script>` |
| `## 注記` セクション | **削除** |

### data属性設計

```html
<article id="creation-five-stages" 
         data-schema="five-stages"
         data-version="1.0">

  <section class="creation-step" 
           data-step="1" 
           data-title="場"
           data-title-en="Field"
           data-bg-concept="Vacuum">
    <dl class="step-attributes">
      <dt>構造</dt><dd>無</dd>
      <dt>プロセス</dt><dd>漂う</dd>
      <dt>イメージ</dt><dd>海のような</dd>
    </dl>
    <div class="step-body">
      <!-- 本文 -->
    </div>
  </section>

  ...

</article>
```

**Step番号 → kesson-spaceの3Dオブジェクトとの対応**:  
`data-step` の値がkesson-spaceのシーン切り替えトリガーになることを想定する。

### パーサー実装メモ

シンプルなパーサーで処理可能な構造にする:

```
1. front matterをJSONに変換 → <script type="application/json">
2. ## Step N で section区切り → data-step="N"
3. **key**: value パターン → <dl><dt>/<dd>
4. それ以外の本文 → <div class="step-body">にmarkdownをそのまま格納
   （marked.js等でレンダリング）
```

## §4 PDF出力ルール（UI層③）

**ビルドスクリプト**: `transform/scripts/build-pdf-creation.sh` v2.0  
**ビルドツール**: pandoc + lualatex  
**読者種別**: pjdhiro（著者）/ general（一般）/ designer（設計者）/ academic（学際）

### ビルドコマンド

```bash
# リポジトリルートで実行
cd ~/dev/kesson-driven-thinking

# 単体ビルド
bash transform/scripts/build-pdf-creation.sh --audience general
bash transform/scripts/build-pdf-creation.sh --audience designer
bash transform/scripts/build-pdf-creation.sh --audience academic

# 全4種ビルド＆pjdhiroリポジトリにpush
bash transform/scripts/build-pdf-creation.sh --audience all --push

# 依存チェックのみ
bash transform/scripts/build-pdf-creation.sh --setup
```

### ソース構造（v2.0）

| audience | ソースファイル |
|----------|-------------|
| pjdhiro | `base/text/m2-creation-process/creation-source.md`（直接変換） |
| general | `transform/guides/drafts/creation-general-draft.md` |
| designer | `transform/guides/drafts/creation-designer-draft.md` |
| academic | `transform/guides/drafts/creation-academic-draft.md` |

各ドラフトは `reader-rules-creation-{audience}.md` に従い変換済み。

### 変換処理（PDF固有）

| ソース要素 | PDF出力 |
|-----------|--------|
| `## Step N タイトル` | `\subsection{Step N: タイトル}` |
| front matter | pandocメタデータとして処理（タイトル・著者等） |
| `## 注記` セクション | **削除**（pjdhiro版のみ strip_notes 適用） |
| `data-*` 属性 | 不使用（pandocが無視） |
| SVG画像 | pandocがPDFに埋め込み |

### レイアウト

`pdf-output-spec.md` の general種別ルールに準拠。  
creation固有の追加設定: なし（既存フローに乗せる）

## §5 共通変換ルール

全出力に適用:

1. **`## 注記` セクションを削除** — [P][M][S]タグは内部作業用
2. **ソースの改行を保持** — 変換層が勝手に段落を結合しない
3. **front matterのメタ情報を活用** — `id`, `tags`, `schema` は各出力のメタデータに引き継ぐ
4. **バージョン管理** — front matter `version` をコメントまたはフッターに付記

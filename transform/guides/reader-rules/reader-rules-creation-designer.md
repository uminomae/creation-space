## §2 中心テーマと設計思想

### 中心テーマ

**「5段階のどこにいるかを診断する」**

発散/収束の二分法では消えてしまう段階——とくに「縁」——を可視化し、創造プロセスの構造的な診断ツールとして5段階を提示する。

### 設計思想

| kesson designer | creation designer |
|----------------|------------------|
| ラベルの分解（共感、直感） | プロセスの分解（発散/収束の間） |
| F-O軸が核心 | 5段階の構造が核心。F-O軸は接続として導入 |
| 共感5層分解が中心実演 | 縁の構造記述が中心実演 |
| 「あなたの中で起きていること」 | 「チームの創造プロセスで起きていること」 |

### 射程についての注記

5段階は「創造プロセスのモデル」ではなく「存在そのものの創造」を記述している（S55）。
チームの創造プロセスは、この5段階が最も体験的に見えやすいスケールの一つである。
本稿はチームプロセスを入口にするが、5段階の射程をチームに限定しない。

## §4 用語変換

### 5段階：構造として提示

名称はそのまま使用。初出で体験的に導入してから構造記述へ。

| 段階 | designer版での導入 |
|------|-------------------|
| 場 | プロジェクト開始前。「何を作るべきか」がまだ見えない。可能性だけが漂う。まだ問いもない。チームが集まったが、方向が定まる前の状態。ここにいる時間は短く見えるが、場の質が後の全段階に影響する |
| 波 | 対立軸が立ち上がる。ユーザーニーズ vs 技術制約、短期 vs 長期。一つの揺れではなく、複数の軸が同時に動く。リサーチが始まり、情報が増えるほど揺れも増える。この段階で「早く決めよう」とすると、波を飛ばして渦に入ることになる |
| 縁 | 矛盾が最大化する。どの対立も「片方を捨てる」だけでは収まらない。ここが最も不快で、最も重要な場所。F軸（早く決めなきゃ）の圧が最も強くなる。縁に留まれるかどうかが、渦の質を決める |
| 渦 | 矛盾の中から方向が生まれる。プロトタイプが立つ。ただし最初のプロトタイプは「これだ」ではなく「こっちの方向だ」。渦は回転している。一度決まっても条件が変われば縁に戻る。渦の質は、縁でどれだけ留まったかに依存する |
| 束 | デリバラブルだが、それだけではない。プロジェクトを通じて獲得された判断基準、再利用可能なパターン、チームの暗黙知が「束」として残る。束を手放して場に戻れるかが、次の創造サイクルの質を決める |

### F-O軸：接続として導入

5段階の中で「なぜ縁に留まれないか」を説明する補助として、F-O軸を接続的に導入する。

- F軸：「早く決めなきゃ」という信号（スプリントの圧、締切の圧）
- O軸：「もう少しこの矛盾に付き合いたい」という引力

### 用語変換表

| 原語 | designer版での表現 |
|------|-------------------|
| 予測誤差 | 「予測とのズレ」「"これじゃない"感覚」 |
| Withhold | 「留まる」「結論を急がない」 |
| Container | 「受け止められるチーム」「心理的な安全」 |
| 内在化 | 「チームの中に内在化された信頼」 |
| 発散/収束 | そのまま使用。ただし「この二分法では消える場所がある」と明示 |

### 温度表現

| 温度 | designer版の表現 | 使いどころ | 割合目安 |
|------|---------------|-----------|---------|
| 確定 | 「〜です」「〜が確認されました」 | 5段階の定義、構造記述 | 15% |
| 有力 | 「〜のように見えます」「〜が見えてきます」 | 各段階の体験描写、接続 | 50% |
| 仮説 | 「〜かもしれません」「試してみてください」 | 読者への問いかけ、チーム適用 | 25% |
| 未解決 | 「〜はまだわかりません」「問いとして残します」 | 保持論点 | 10% |

### 使用禁止

- [P][M][S]タグ
- Layer番号
- 数理表現、スピノル
- α機能、β要素、投影同一化等の精神分析用語
- PS↔D

## §5 3幕構成

```
入口: 「発散と収束の二語では名前がつかない場所」
  ダブルダイヤモンドの経験。発散して、収束する。
  でも、その間に「どっちでもない」時間がある。
  → 読者の自己選択: 「ある。あの居心地の悪い時間」

第1幕: 5段階のどこにいるか
  発散/収束は2段階。でも実際には5段階ある。
  場（何もない）→ 波（揺れる）→ 縁（矛盾が最大化）
  → 渦（まとまる）→ 束（残る）
  診断の道具として: 「今チームはどこにいるか？」
  → 各段階の「観察できるサイン」と「落とし穴」
  → 途中の安全弁（§7-b）をここに挿入

第2幕: 縁で逃げない技術
  縁は最も不快な場所。
  F軸（「早く決めなきゃ」）が最も強く働く。
  O軸（「もう少しこの矛盾に付き合いたい」）は小さい。
  ここでF軸に負けると、渦の質が下がる。
  → Withhold の導入: 「結論を急がず、矛盾を保持する」
  → チームでWithholdするための条件
    （安心できる関係 = Container）
  → 欠損駆動思考との接続:
    「Withholdされた問いが5段階を通って構造になる」

第3幕: チームの創造プロセスの可視化
  5段階はチームでも同じ構造。
  個人の「場→束」と、チームの「場→束」は入れ子になる。
  チームの創造プロセスを可視化するには:
  「今、チームとして5段階のどこにいるか」を問う。
  → 束→場の循環: 「作ったものを手放す」難しさ
  → 「保持するチーム」と「保持しないチーム」の長期的な差

出口: 返却の設計（§7-b）
  「あなたのチームが最近『早く決めよう』と言ったとき、
   それは何段階目でしたか」
  + 返却
```

## §7-b 返却の設計

kesson designer v2.1 §7-b を継承。NL-001+ に準拠。

### 返却の3要素

#### 1) 途中の安全弁（第1幕終了後に1箇所）

**パターンA**:
> 「この5段階は、私がプロジェクトを観察して見えた構造です。確定しているところと、まだ仮説のところがあります。次のパートで、どこが確定でどこが仮説かを正直に示します」

#### 2) 結びの安全弁（必須）

**パターンA（温度開示型）**:
> 「5段階の構造記述と縁の中心性は、30領域の調査で繰り返し確認されました。チームプロセスへの適用は、私の観察にもとづく仮説です。確定を待つのではなく、あなたのチームで試してみて、合うかどうかを見てください」

**パターンB（関与L0型）**:
> 「返信や感想はなくて大丈夫です。地図の上で一つ、チームの現在地が見えたなら、それだけで十分です」

#### 3) 関与レベル

PDFのデフォルトは **L0**。

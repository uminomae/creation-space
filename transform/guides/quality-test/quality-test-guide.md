# ルール評価基準: 解説書(guides) v1.0

**目的**: 解説書の生成物を読んで「evidence 逸脱・ルール違反がないか」を特定するための観点リスト
**使用者**: pjdhiro（人間によるレビュー）および Claude Code（生成後自己チェック）
**判定**: PASS / WARN（要目視） / FAIL
**再生成基準**: FAIL が1件でもあれば再生成。WARN は3件以上で再生成を検討。
**背景**: cs#166, cs#167 で evidence にない理論・主張が混入したため制定。

---

## カテゴリ1: Evidence 裏付け（最優先）

### G1-1: 先行研究者名・理論名が evidence に存在するか

解説書に登場する先行研究者名・理論名が、`evidence/evidence-D*.md` に [P]層 または [M]層 エントリとして存在するか。

チェック方法:
1. 解説書から研究者名・理論名を抽出する
2. 各名称について evidence を検索する

```bash
# 例: Csikszentmihalyi が evidence に存在するか
grep -rl "Csikszentmihalyi" evidence/evidence-D*.md

# 例: ガイド内の大文字始まりの人名候補を抽出
grep -oE '[A-Z][a-z]{2,}([ -][A-Z][a-z]+)*' {ガイドファイルパス} | sort -u
```

evidence に存在しない研究者・理論が1件でもあれば FAIL。

### G1-2: 因果方向が正しいか（cs#166 の T1-5 継承）

5段階モデルが30領域の調査から導出・発見されたと読める表現がないか。
正しい因果: モデルは pjdhiro が体験から言語化。調査はモデルと既知概念の構造対応を探索・検証するため。

```bash
grep -in "調査から見出\|調査により発見\|調査に基づいて構築\|調査から.*導出\|investigation revealed\|discovered through\|derived from.*survey\|見出されたもの" {ガイドファイルパス}
```

該当があれば FAIL。

### G1-3: [M]層の記述が断定になっていないか

evidence の [M]層（構造的類似の読み取り）由来の内容が、「〜である」「〜と証明されている」等の断定表現で記述されていないか。

チェック方法:
1. 解説書内の理論対応記述を特定する
2. 該当する evidence エントリの層（P/M）を確認する
3. [M]層由来の記述が「〜と構造的に対応する」「〜として読める」等の解釈表現になっているか確認する

断定表現の [M]層記述があれば FAIL。

### G1-4: 定量的主張に evidence の集計根拠があるか

「最も多い」「N領域で確認された」「大半の領域で」等の定量的主張がある場合、evidence の実際の集計で裏付けられるか。

```bash
grep -in "最も多\|[0-9]*領域で.*確認\|most domains\|majority of\|大半の\|独立に確認" {ガイドファイルパス}
```

該当があれば WARN（目視で evidence との照合が必要）。evidence に根拠がなければ FAIL。

### G1-5: 因果断定がないか

「〜が質を決める」「〜を保証する」「determines the quality」等の因果断定がないか。
evidence が因果を確認していない限り、「〜と対応している」「〜と関連する」に留めること。

```bash
grep -in "質を決める\|を保証する\|determines\|guarantees\|ensures.*quality\|が.*を規定" {ガイドファイルパス}
```

evidence に因果の根拠がない因果断定があれば FAIL。

## カテゴリ2: 正本との整合

### G2-1: 5段階の名称・構造・プロセスが five-stages.md と一致するか

5段階の名称、各段階の説明、プロセスの流れが `knowledge/schema/five-stages.md` の定義と一致しているか。
段階の名称変更、順序の入れ替え、定義の改変がないか。

該当があれば FAIL。

### G2-2: 正本にない主張が混入していないか

five-stages.md に明記されていない概念（「逆行」「螺旋」「reversal」「spiral」等）が、あたかもモデルの一部であるかのように記述されていないか。

```bash
grep -in "逆行\|螺旋\|reversal\|spiral\|循環\|cycle\|ループ\|loop" {ガイドファイルパス}
```

該当があれば WARN（five-stages.md と照合して判定）。正本にない概念がモデルの一部として記述されていれば FAIL。

## カテゴリ3: 禁止パターン

### G3-1: 因果逆転パターン（cs#166）

G1-2 と同一。因果逆転表現がないか。

### G3-2: 既存禁止パターン

以下がないか:
- 「ピンとこなければ大丈夫です」型の謙遜
- 「あらゆる創造に〜」「全ての人が〜」の普遍化断定
- 「これを使えば〜」の効果の約束
- 「〜のモデルは不十分」の先行研究攻撃
- 「本モデルが既存理論を統合する」のメタ理論の僭越

```bash
grep -in "ピンとこなければ\|あらゆる創造\|全ての人が\|これを使えば\|不十分\|統合する" {ガイドファイルパス}
```

該当があれば WARN（文脈次第で FAIL）。

### G3-3: Evidence にない理論の言及

G1-1 と同一。evidence にない理論・研究者が言及されていないか。

## カテゴリ4: 温度の適切性

### G4-1: 仮説を断定として記述していないか

「〜かもしれない」「〜と考えられる」レベルの仮説が、「〜である」「〜が示されている」等の断定で記述されていないか。

チェック方法: 解説書内の主張を1つずつ確認し、evidence の裏付け強度に対して温度が適切か判定する。

断定温度で仮説を記述していれば FAIL。

### G4-2: Evidence の層（P/M）に応じた温度になっているか

temperature ルール（`evidence-constraint.md` 3節）に従っているか。

| Evidence 層 | 許容温度 |
|------------|---------|
| [P]層 | 「〜である」（事実記述可） |
| [M]層 | 「〜と構造的に対応する」「〜として読める」（解釈記述） |
| Evidence なし | 記述禁止 |

層と温度の不一致があれば FAIL。

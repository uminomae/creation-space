# CL-006: 場当たり的修正の連鎖は最初の変更の影響分析不足が原因

**日付**: 2026-03-15
**関連Issue**: cs#65-75

## 何が起きたか

問題2（reports が消えた）を修正する過程で問題3（taxonomy が消えた）に気づき、問題3を修正する過程で問題6（unknown 表示）に気づいた。各修正が新たな問題の発見を引き起こす「もぐら叩き」パターンが発生した。関連コミット: 5fa4b73, c560d69, 677d9b8, b8566e7, a13063f, 302db50。

## 原因分析

最初の変更（cs#74 子Issue 3 でのフィールド名変更）が影響範囲を十分に分析せずに投入されたため、後続の修正が連鎖した。1つの上流変更が複数の下流障害を引き起こし、それぞれを個別に修正する「もぐら叩き」になった。影響分析を事前に行っていれば、1回の変更で全箇所を同時に修正できた。

## 対策

1. 破壊的変更を投入する前に、下流消費者を全列挙し影響を分析する
2. 破壊的変更と下流の修正は同一コミットまたは同一タスクで行い、中間状態で不整合を発生させない
3. Agent プロンプトに下流消費者リストを明記する

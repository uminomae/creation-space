# CL-004: フィールド名・キー名の変更は破壊的変更。後方互換フォールバック必須

**日付**: 2026-03-15
**関連Issue**: cs#74

## 何が起きたか

cs#74 子Issue 3 で `index.json` の `progress_model` を `generator_model` にリネームした。フロントエンド (`data.js`) は `payload.reports` キーを期待していたが、生成された `domains.json` のキー構造が変わったことで空配列が返され、全領域が消えた。さらに「生成モデル: unknown」が全カードに冗長表示された。

## 原因分析

フィールド名の変更は破壊的変更であるにもかかわらず、通常のリファクタリングとして扱われた。下流の `data.js` に後方互換のフォールバック（旧キー名でも読めるガード）が存在せず、一箇所の変更が複数の表示障害を引き起こした。

## 対策

1. フィールド名・キー名の変更は破壊的変更として扱い、専用チェックリストを適用する
2. 下流消費者に後方互換フォールバックを実装する（旧キーでも動作するガード）
3. 破壊的変更と下流の修正は同一コミットまたは同一タスクで行う

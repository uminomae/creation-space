# CL-005: フロントエンド変更はビジュアル検証なしに品質保証できない（CLI の構造的限界）

**日付**: 2026-03-15
**関連Issue**: cs#75

## 何が起きたか

cs#75 の Agent が `modal-header` の CSS を変更したが、`justify-content: space-between` を設定しなかったため、PDFボタンと閉じるボタンが左に固まるレイアウト崩れが発生した。Agent はCSSを書いたがレンダリング結果を確認する手段を持たず、デプロイ後に pjdhiro が目視で発見した。

## 原因分析

1. 静的サイトのフロントエンド変更を CLI 環境から検証する手段がない。CI/CD パイプラインもない。
2. UI 変更の完了条件にビジュアル検証が含まれていなかった。
3. Agent はプロンプトに書かれた範囲のファイルしか見ない傾向があり、レイアウト要件が具体的なCSSプロパティ値まで指定されていなかった。

## 対策

1. レイアウトに関わるCSS変更は、Agent に任せるよりも Main で対話的に実施する方が安全
2. Agent に投げる場合は、具体的なCSSプロパティ値まで指定する
3. 長期的にはフロントエンドの smoke test（スキーマ検証など）を導入する

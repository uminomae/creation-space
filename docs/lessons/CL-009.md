# CL-009: 同一原典の同一領域重複と「テストの無いワークフロー」

**日付**: 2026-06-22
**関連Issue**: cs#249

## 何が起きたか

source-note backfill 中、`knowledge/raw/manifest.md` に同一原典・同一領域の重複行が見つかった。

- `D15-S09` / `D15-S10` = Dewey 1934 *Art as Experience*（同一書・同一領域 D15）
- `D26-S06` / `D26-S09` = Huron 2006 *Sweet Anticipation*（同一書・同一領域 D26）
- `D25-S01` / `D25-S01b` = van Gennep 1960英訳（raw 物理重複）

しかも `D26-S09` と `D25-S01b` は manifest 注記に**すでに「=重複」と書かれながら除外されず放置**されていた。pjdhiro は「明らかなミス、2度とあってはならない」と問題視。

## 原因分析

1. **構造的要因**: source-note 生成ワークフローに「原典重複」を検出する自動テストが存在しなかった。`validate-manifest-sync.sh` は 1:1 原則（行→source-note）は見るが、行どうしの重複は見ていなかった。
2. **運用的要因**: 重複に気づいても「注記して放置」する文化があった。注記は検知の代替にならない。
3. **メタ要因**: ワークフローと品質書類（特に自動テスト）の対応が体系化されておらず、「テストの無いワークフロー」が放置されていた。

## 対策

1. **重複行の除外**: `D15-S10` / `D26-S09` を manifest から除外。`D25-S01b` は物理PDF削除を伴うため当初 pjdhiro 判断待ちとしたが、2026-06-22 に承認を得て物理PDF（`D25_vangennep_1909_rites-of-passage.pdf`、D25-S01 と MD5 一致）・manifest 行・`REVIEWED_DUP_EXCEPTIONS` 登録とも除外済み。
2. **自動検知**: `validate-manifest-sync.sh` に **Check 10**（原典重複検知, FAIL）を新設。`(領域,著者姓,年,書名)` で重複群を検出。クロス領域anchorは領域差で非該当、版違い等は `REVIEWED_DUP_EXCEPTIONS` でレビュー済のみ通す。
3. **不変条件の明文化**: `CLAUDE.md`（毎セッションロード）と `.claude/rules/source-note-invariants.md` §2.5 に「原典重複禁止」を記載。「気づいたら注記放置せず即除外」を運用ルール化。
4. **品質管理の体系化**: `docs/quality-management.md` に §7 自動テストカタログ / §8 ワークフロー×品質書類対応表 / §9 定期網羅ランブックを追加。網羅ランナー `scripts/qc-all.sh` を新設。**「テストの無いワークフローを作らない」**を不変原則化。

# CL-003: データパイプラインの上流変更は下流消費者を全列挙してから投入すべき

**日付**: 2026-03-15
**関連Issue**: cs#74

## 何が起きたか

cs#74 子Issue 3 で `index.json` のフィールド名を変更した際、Agent はパイプラインの上流（index.json + generate-domains-json.mjs）のみを変更し、下流（data.js のパース処理）への影響を検証しなかった。結果として Reports コンテンツが全て消え（総領域: 0）、分類表示（progress_taxonomy）も消えた。

## 原因分析

`index.json` → `generate-domains-json.mjs` → `domains.json` → フロントエンド (`data.js`) という4段のパイプラインがあるが、上流の変更を投入する際に下流消費者のリストが Agent に提示されていなかった。Agent は与えられたファイル範囲でのみ作業する傾向があり、データフロー全体を自発的に追跡しなかった。

## 対策

1. データパイプラインの上流を変更するタスクでは、下流の全消費者を列挙してから投入する
2. Agent プロンプトに「変更対象ファイルの下流消費者」を明記する

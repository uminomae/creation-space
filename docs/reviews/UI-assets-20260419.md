作成日: 2026-04-19
対象 repo: creation-space
棚卸し方式: 静的読解ベース（HTML + tokens.css + dev-components.html の宣言）
判定記号: KEEP（温存）/ SYSTEMIZE（token/component 化候補）/ DROP（削除候補）

## index.html

「創造とは」ランディング。Three.js canvas + REPORTS / CROSS ANALYSIS セクション列 + 30領域調査 hover-grid モーダル。kesson-space と共通骨格（topbar / room-narration / section-heading）を共有。

### レイアウト
- **Three.js canvas + creation-main の z-index 分離**: kesson と同パターン。KEEP
- **`#main-content .creation-main`** を main ランドマーク化: a11y 向上。KEEP
- **graphic-switcher（忍/意 切替 toolbar）**: 左上固定の 2 button、背景モード切替。他 repo にないユニーク機能。KEEP
- **section 連鎖**（model / reports / cross-analysis / articles）: 理論 → 調査 → 横断分析 → 記事。順序そのものが創造5段階モデルのメタファー。KEEP
- **hover-grid-modal（fullscreen 全画面）**: techo#53 由来。30領域を一望するビュー。KEEP
- **reports-stack（縦積みセクション group）**: `section > reports-stack-section` のネスト。KEEP

### アニメーション
- **room-narration 幕間**（text 静的配置、`<br>` で改行調整）: kesson と共通意図、creation は narration 回数が多い（3 箇所）。KEEP
- **scroll-hint / scroll-hint-top**: kesson と共通。KEEP
- **graphic-switcher は animation なし**: 状態が `aria-pressed` のみで切替。KEEP（機能と UI の一致）
- **phase9-toggle**: Bootstrap collapse で段階検証を折り畳み。アコーディオン的。KEEP
- **startup-error overlay の pre 要素 append**: エラー時のみ可視化、動的追加。KEEP（可視化の潔さ、本番画面でも動く）

### 配色
- **kesson と同一 core token**（`--color-accent`, `--color-bg-body`, etc.）: tokens.css に `"Intentional difference vs awareness-space"` コメント、意識的差分保持。SYSTEMIZE（core token は pd 集約、差分は local override で保持）
- **`--cs-surface-1/2/3`**（半透明濃紺 3 階調、0.3/0.6/0.9）: kesson の単一 `--kesson-card-bg` を階調化。KEEP — 層構造で深さを表現できる
- **`--reports-palette-1～10-rgb`**（10 段パレット）: 30領域調査の色分け。palette-3 を default （accent 青）に持ってくる。KEEP — 調査の性質と一致した設計。SYSTEMIZE は不可（reports 専用の文脈依存）
- **`--cs-font-sans-ui: Noto Sans JP`** 追加: kesson にない sans 系。UI 本文で明朝を避けたい時用。KEEP

### タイポグラフィ
- **Noto Serif JP + SF Mono + Noto Sans JP の三本柱**（kesson は二本柱）: creation は調査レポート本文で sans を使う。KEEP — 調査本文の可読性確保
- **`--kesson-font-mono-ui` を `--reports-font-mono` にエイリアス**（reports-demo-scope 内）: scope ごとに別名化する設計。KEEP
- **narration で `<br>` による改行制御** ("ひとつの問いから始まりました。<br>三十の領域が、同じ方向を指していたのです。"): 詩的な間。KEEP — アニメ不採用と併せた強い意図
- **`--reports-control-font-size: clamp()`** with `--reports-font-step` dynamic: 実行時に font-step で可変、ユーザーの文字サイズ調整と連動。KEEP（技術的巧妙）

### 触覚的要素
- **ds-summary-card の `border-radius: 1rem`**（kesson の 3px よりかなり大きい）: dev-components 限定でふっくらさせる意図。KEEP（仕様書だけの柔らかさ）
- **ds-swatch-chip `height: 5.5rem`**: 色見本を大きく取る。KEEP
- **radial-gradient（ds-summary-card bg）**: `circle at top right, rgba(accent, 0.08), transparent 38%` → 角から光がにじむ表現。KEEP — `--cs-surface-*` の平坦さとの対比
- **`box-shadow: 0 20px 60px rgba(0, 0, 0, 0.26)`**（ds-section / ds-component）: 強めの影。kesson の accent 色影と方向性が異なる。creation は黒影で floating を強調。ブランド判断要（B フェーズで統一 or 区別）
- **hover-grid-modal の fullscreen**（`position: fixed; inset: 0`）: 通常の modal と異なる scope。KEEP

### インタラクション
- **i18n 方式: `data-i18n` + dictionary + `data-i18n-attr-aria-label`**: kesson の `data-ja/data-en`（leaf に直書き）より高機能、aria-label も i18n 化。SYSTEMIZE（単一ソース化する場合 i18n 方式を統一するか決定必要。creation 方式のほうが拡張性高い）
- **data-i18n-html** 属性: innerHTML にマークアップ付き文字列を挿入。`<br>` 改行を含む narration で使用。KEEP
- **graphic-switcher aria-pressed toggle**: radio button ではなく aria-pressed で実装。KEEP
- **phase9-toggle collapse / reports-open-status-btn**: Bootstrap 標準 + 独自ボタン。SYSTEMIZE（標準パターン、component 化可能）
- **font-size-down/reset/up**: topbar 常設（kesson と共通）。SYSTEMIZE
- **startup-error 監視（error / unhandledrejection 両方 listen）**: 本番でも boot 失敗を可視化。KEEP — kesson にない手法、単一ソース化する価値あり
- **hover-grid-open-btn は `?grid=hover` URL param で可視化**: techo#53 の方式。KEEP

### index.html 特有の所見
- **REPORTS の構造が密**: filters / metrics / domain-grid / phase8-grid / phase9-collapse / theme-verification-grid / scenario-note / level-legend。階層が 5 層、Bootstrap + 独自 class の混合。観点B 時に「レポート表示 pattern」として component 化する価値は高いが、専用性が強いため抽出は慎重に

## dev-components.html

自己記述ページ。1414 行、kesson の design-system.html より大きい。カテゴリ分類より「runtime surface」「demo shell」で構成され、実動する components を並べて検証する目的。

### レイアウト
- **`.ds-section / .ds-component / .ds-demo-shell / .ds-report-palette / .ds-runtime-surface`** の 5 コンテナ体系: kesson design-system より実装寄り。KEEP（repo 独自）

- **ds-summary-grid（180px min + auto-fit）**: カード並びの自動 wrap grid。kesson は固定 Bootstrap grid、cs は CSS Grid で fluid。KEEP — 仕様書向きの柔軟さ
- **max-width: 1120px**（kesson の 960px より広い）: 1414 行の内容量に対応。KEEP

### アニメーション
- **`scroll-behavior: smooth`**: アンカー移動を滑らかに。KEEP（仕様書で特に有効）
- **本番 UI の `#scroll-hint` / `#graphic-switcher` / `#control-guide` / `#dev-panel-toggle` を static 配置で表示**: 実装の「生」を見せる。KEEP — design system の独自価値

### 配色
- **ds-summary-card の radial-gradient**（`circle at top right, rgba(accent, 0.08), transparent 38%` + `rgba(9, 13, 24, 0.78)` base）: kesson にない表現。KEEP
- **`--reports-palette-1～10`** 10 段: design-system で全palette 可視化。KEEP
- **ds-swatch-chip bg に `inset 0 1px 0 rgba(255, 255, 255, 0.03)`**: 色チップに極微細 hairline 上光沢。KEEP — 手作りディテール

### タイポグラフィ
- **`.ds-kicker`**（border-radius: 999px, letter-spacing: 0.08em, uppercase, kesson accent border）: pill 状の目印。KEEP
- **h2 に `font-size: clamp(1rem, 2vw, 1.35rem)`**: 仕様書の見出しに clamp、ビューポート適応。KEEP

### 触覚的要素
- **`.ds-variable-table`**（0.76rem mono, bg rgba(0,0,0,0.12), border-radius 0.8rem）: token 一覧の専用表。KEEP — SYSTEMIZE 候補（pd に集約時のフォーマット雛形）
- **`.ds-token-pill`**（pill 状、inline-flex、accent 色）: トークン名の視覚化。KEEP
- **`.ds-runtime-row` の再配置**（position: static! important で本番 UI を一時的に static 化）: 実動 UI を仕様書に埋め込む技法。KEEP — 価値が高い
- **@media (max-width: 720px) で `padding: 0 1rem 3rem !important`**: モバイル対応。KEEP

### インタラクション
- **`#reports-demo-scope` で scoped CSS variables**: `--reports-*` を scope 内で redefine、demo が本番 UI を汚染しない。KEEP — 重要な技法、SYSTEMIZE（全 repo の design-system で統一運用可）
- **`.ds-topbar-demo .topbar-status-badge` yellow override**: demo 専用のアラート色。KEEP
- **form-control / form-range / form-check の完全実装**: Bootstrap の完成度に任せず、kesson-* token で上書き。KEEP

### dev-components.html 特有の所見
- **仕様書ではなく「実行可能カタログ」**: kesson の design-system.html が spec table 中心なのに対し、creation は実体を並べて validate する方向性。哲学が異なる
- **`#reports-demo-scope` の scoped var 方式**: pd 集約時の「repo ごとの token override」仕組みとして参考価値が高い

## サマリ

### 定量
- **KEEP 要素数**: 約 42
- **SYSTEMIZE 要素数**: 約 10（観点B / C で集約候補）
- **DROP 要素数**: 0（現状、惰性要素は見当たらない）

### 全 repo 共通化できそうな要素（観点B で pd 集約優先）

1. **core color token セット**（kesson と共通: `--color-accent / --color-sub-text / --color-highlight / --color-heading / --color-bg-body / --color-link`）
2. **letter-spacing / radius / transition tokens**（kesson と共通）
3. **明朝 + mono フォント規約**（kesson と共通）。加えて **`--cs-font-sans-ui`（Noto Sans JP）** を「本文 sans トリプル」として拡張できるか要判断
4. **section-heading / section-heading-link / room-narration / kesson-card / card-grid**（kesson と共通）
5. **viewer glass, focus-ring, error color**（kesson と共通）
6. **`--cs-surface-1/2/3` の 3 階調**: kesson の単一 card-bg を拡張する価値あり。pd 集約時に `--surface-*` 3 階調で統一候補
7. **i18n 方式（`data-i18n` + `data-i18n-attr-*` + `data-i18n-html`）**: kesson の `data-ja/data-en` より高機能。単一ソース化時は creation 方式を採用を推奨
8. **startup-error overlay**: 本番で boot 失敗を可視化する手法、全 repo 展開候補
9. **clear-storage.html**: dev utility、全 repo で同一 URL で提供できる
10. **`#reports-demo-scope` の scoped CSS variables**: design system で repo ごとの override を安全にやる仕組み、pd 集約時の雛形

### 判断の非自明点

- **`--kesson-*` prefix と `--cs-*` prefix の共存**: tokens.css は意図的に `cs` を追加している。pd 集約時に prefix を `--ds-*` に統一するか、全 repo で `--kesson-*` 継承して `--cs-*` / `--as-*` / `--pd-*` を local additions にするかは観点C の決定事項
- **creation の box-shadow は黒影強め（`0 20px 60px rgba(0,0,0,0.26)`）、kesson は accent 色影**: ブランド判断が分かれる。pd 集約時に「影の思想」を決める必要
- **30領域調査パレット（`--reports-palette-*`）は creation 固有**: 単一ソースには入れない、repo local token とすべき
- **dev-components.html が「実行可能カタログ」方式、kesson の design-system.html が「仕様 table」方式**: 統合するか、二本立てにするかは観点B 時の大論点。統合するなら creation 方式のほうが拡張性が高い

### 気づき（観点B で先に決めたほうが良いこと）

- **`"Intentional difference vs awareness-space"` コメント**: tokens.css の冒頭に明記されている。creation と awareness で意識的に差分を保持している事実 → pd 集約時に **「core は集約、surface-level は repo 個性」** という方針が既に現れている。これを正式化すべき
- **hover-grid-modal は techo#53 由来**: techo で PoC された UI が creation に移植されている。この migration pattern（techo → 本 repo）は今後も続く想定 → pd の design system にも「techo 由来の実験的 component」カテゴリを設ける価値
- **i18n 方式の不統一**（kesson: data-ja/data-en, creation: data-i18n）: **観点B で先に決めなければ**、aria-label の i18n 対応差が固定化する
